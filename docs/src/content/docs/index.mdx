## Why

The Proxmox VE web interface is made for clicking, one object at a time. The API behind it can do
everything the interface does, but calling it by hand means a login, a ticket, a CSRF token and a
`curl` line for each call. [`pvesh`](https://pve.proxmox.com/pve-docs/pvesh.1.html) is simpler, but it
runs only on a node, as root, and knows only the cluster that node belongs to.

cv4pve-cli puts the whole API in a command you run from your own workstation. You save each cluster
once, switch between them by name, and type `do start vm --guest web01` instead of looking up which
node the guest runs on. Every API call the web interface makes, you can make from a shell script, a
scheduled job or an AI coding assistant, against as many clusters as you manage.

## Outside the nodes, API only

cv4pve-cli runs outside the cluster (on Windows, Linux or macOS) and talks only to the Proxmox VE REST
API on port 8006. Nothing is installed on the nodes and no SSH is needed. It can do exactly what its
account is allowed to do, so give it a dedicated API token with the privileges you want it to have:
see [Permissions](/cv4pve-cli/permissions/).

| | **cv4pve-cli** | [pvesh](https://pve.proxmox.com/pve-docs/pvesh.1.html) |
|---|---|---|
| **Runs on** | Your workstation, a management VM, a CI runner | A Proxmox VE node |
| **Account** | Any user or API token, with its own privileges | root on the node |
| **Clusters** | Any number, as saved contexts | The one the node belongs to |
| **API calls** | `api get/set/create/delete/ls/usage` | `get/set/create/delete/ls/usage` |
| **Shortcuts** | <AliasCount /> built-in aliases, plus your own | - |

The [Coming from pvesh](/cv4pve-cli/coming-from-pvesh/) page maps each pvesh command to cv4pve-cli.

## Where it fits

The cv4pve suite follows the Unix philosophy: each tool does one thing and does it well. cv4pve-cli is
the general-purpose one: any API call, by hand or in a script. The others answer one question each and
run on their own:

| Tool | Use it for |
|---|---|
| **cv4pve-cli** | Any API call from a shell: read, change, automate |
| [cv4pve-api-powershell](https://corsinvest.github.io/cv4pve-api-powershell/) | The same API as PowerShell cmdlets, with objects instead of text, the choice if your scripts are PowerShell |
| [cv4pve-report](https://corsinvest.github.io/cv4pve-report/) | The full inventory of a cluster, in Excel, HTML or JSON |
| [cv4pve-diag](https://corsinvest.github.io/cv4pve-diag/) | What is wrong in a cluster: a list of problems, each with a severity |
| [cv4pve-admin](https://corsinvest.github.io/cv4pve-admin/) | A web platform for several clusters, when a command line is not what you want |
