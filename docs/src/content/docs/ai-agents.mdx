An AI coding assistant that can run shell commands can use cv4pve-cli to read and operate a Proxmox VE
cluster: it discovers the API with `api ls` and `api usage`, reads JSON with `-o json`, and needs no
SSH access to the nodes. What it can do is exactly what the token of its context allows — so the token
is where you decide how far the assistant can go.

## Give it a token of its own

Create a context for the assistant with a dedicated API token:

- **`PVEAuditor`** for looking only: the assistant reads configuration and status, and Proxmox VE refuses
  anything else, whatever command it runs. See [Permissions](/cv4pve-cli/permissions/).
- A wider role only for the operations you want it to run, on the pool or the guests concerned.

Do not rely on the assistant, or on cv4pve-cli, to stop a destructive command: `do`, `create`, `set`
and `delete` aliases and `api` calls run at once, and `--yes` does not stop them in the current version
— see [Operations that change the cluster](/cv4pve-cli/aliases/#operations-that-change-the-cluster).

## Sandboxes

The assistant runs cv4pve-cli with its own permissions, often inside a sandbox. cv4pve-cli needs:

- to connect to the node on port 8006;
- to write in `~/.cv4pve/` — contexts, the API schema cache and the daily update check. Without the
  API schema cache `api` commands and aliases fail.

On Windows, Claude Code and other assistants often run commands in Git Bash, which rewrites API paths
such as `/version` into Windows paths: set `MSYS_NO_PATHCONV=1` in their environment — see
[Git Bash on Windows](/cv4pve-cli/troubleshooting/#git-bash-on-windows).

On its first run cv4pve-cli also adds a line to `~/.bashrc` and `~/.zshrc`, or to the PowerShell profile,
to set up [tab completion](/cv4pve-cli/completion/). An assistant has no use for it; if the sandbox
blocks the write, cv4pve-cli goes on without it.

The settings below were reported by a user in
[issue #10](https://github.com/Corsinvest/cv4pve-cli/issues/10) — thanks to
[@cheriot](https://github.com/cheriot). Check them against the documentation of your assistant.

### Claude Code on macOS

With a self-signed certificate, turning certificate validation off on the context
(`--validate-certificate false`) was not enough in the Claude Code sandbox on macOS: every HTTPS
connection still asks the macOS trust service, and the sandbox blocked that lookup. The fix reported in
the issue, in `.claude/settings.json`:

```json
{
  "permissions": {
    "allow": ["WebFetch(domain:$PROXMOX_IP)"]
  },
  "sandbox": {
    "network": {
      "allowMachLookup": ["com.apple.trustd*"]
    },
    "filesystem": {
      "allowWrite": ["~/.cv4pve/"]
    }
  }
}
```

### Codex

Codex needed only a rule that allows the command, in `~/.codex/rules/default.rules` — in the issue, with
a token of the auditor role:

```text
prefix_rule(pattern=["cv4pve-cli"], decision="allow")
```

## A SKILL.md for the project

A short description of the tool in the project is often enough to make the assistant productive. A
starting point:

```markdown
# cv4pve-cli

Command-line client for the Proxmox VE API. Use it for every read or change on the
cluster instead of SSH to a node.

## Context
A context named `lab` is configured and current. Do not add, change or switch contexts.

## Commands
- `cv4pve-cli top -o json`                    — every resource of the cluster
- `cv4pve-cli get vms -o json`                — VMs and containers
- `cv4pve-cli api get /nodes/<node>/qemu/<vmid>/config -v` — configuration of a VM, disks and NICs included
- `cv4pve-cli api get <path> -o json`         — any API read
- `cv4pve-cli api ls <path>`                  — what is under a path
- `cv4pve-cli api usage <path> [method] -v`   — parameters a path accepts

## Rules
- Use `--guest <name|id>` instead of looking up node and VM ID.
- Use `-o json` to read lists; for configurations use `api get … -v` (`-o json` leaves out net0, scsi0…).
- Never run `do`, `create`, `set`, `delete` or `api set/create/delete` without asking first.
- Check results, not exit codes: API errors exit with 0.
```

Adapt the context section to the token you gave it.
