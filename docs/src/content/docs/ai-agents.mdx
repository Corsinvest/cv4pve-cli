An AI assistant that can run shell commands can use cv4pve-cli to read and operate a Proxmox VE
cluster: it discovers the API with `api ls` and `api usage`, reads JSON with `-o json`, and needs no
SSH access to the nodes.

## The cv4pve-cli skill

<AiSkill tool="cv4pve-cli">

- leave the contexts alone and read with `-o json`;
- explore the API with `alias list --search`, `api ls` and `api usage -v`;
- run every change first with `--dry-run`, and for real only after you agree, adding `--yes` where needed.

</AiSkill>

## Give it a token of its own

The skill tells the assistant what to do; the token decides what it can do. cv4pve-cli asks `--yes` only
for the aliases that cannot be undone; `api` calls and the other aliases run at once (see
[Operations that change the cluster](/cv4pve-cli/aliases/#operations-that-change-the-cluster)), and the
skill cannot prevent that. Create a context for the assistant with a token of its own: `PVEAuditor` if
it only reads, otherwise a role with only the operations you want it to run, on the pool or the guests
concerned. See [Permissions](/cv4pve-cli/permissions/#which-role).

cv4pve-cli must be able to write in `~/.cv4pve/`, where it keeps the contexts and the API schema cache:
an assistant that runs in a sandbox needs that folder allowed. In Git Bash on Windows it also needs
`MSYS_NO_PATHCONV=1` (see [Git Bash on Windows](/cv4pve-cli/troubleshooting/#git-bash-on-windows)). The
settings a user needed for Claude Code on macOS and for Codex are in
[issue #10](https://github.com/Corsinvest/cv4pve-cli/issues/10).
